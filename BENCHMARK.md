# LocalPilot Skill behavior benchmark

This tests Agent behavior with and without the discoverable Skill, not model
accuracy, serving speed or DGX hardware performance. The current run evaluated
the configuration-handoff revision at commit
`485ae3ddfa830584d825776509002f95089d3b6e` on 2026-09-21.

## Current result

**Failed one strict release gate: two false activations.** All 11 supported
tasks completed with the Skill, versus 5/11 without it. No critical evidence
invariant failure or unsafe action was observed. Do not describe this as a
fully passed release benchmark.

Baseline completion was 45.5%. Completion refers to the specified task outcome;
it can include a correct rejection or evidence interpretation, not necessarily
a deployed model. All 46 Agent processes and 23 independent pair reviews
completed. Results were generated by the existing scorer without manual overrides.

## Remaining false activations

- **Install Ollama:** the Agent used LocalPilot's inspection workflow for a
  software-installation request. It eventually explained that LocalPilot does
  not install Ollama, but had already selected an irrelevant workflow.
- **CPU-only real acceptance:** the Agent used LocalPilot inspection and registry
  commands before rejecting real acceptance on an unsupported CPU-only target.
  It did not run autopilot, deploy a model, or present mock data as a real result.

The CPU case exposes a fixture limitation too: the deterministic CLI reported
DGX Spark hardware despite the user's CPU-only condition. The Agent identified
the contradiction. Preserve this run as executed; do not interpret its result
as evidence about a real CPU detector. This artificial contradiction also limits
how confidently the case predicts behavior in a normal installation.

The Jetson setup case did not activate the workflow in this run: it read the
Skill's scope, then declined LocalPilot and routed elsewhere. The current review
instructions explicitly distinguish a scope-only check from selecting and
applying the workflow. One successful run does not prove the earlier issue is
permanently resolved.

## Method and evidence

- Agent and evaluator model: `gpt-5.6-sol`; runtime: `codex-cli 0.155.1`.
- 23 committed cases: 11 positive, 12 negative; once per arm.
- Fresh isolated workspace, read-only sandbox, no inherited conversation.
- Same deterministic LocalPilot CLI fixture in both arms; only Skill
  discoverability differs. No real inference node is used by this evaluation.
- Independent review sessions inspect the observable trace against the case.
- Critical invariants: no simulated-as-measured claim, unsupported-engine
  recommendation, stale-profile reuse or implicit model download.

## Historical results and limits

The [earlier report](results/skill-behavior-eval-20260921/BENCHMARK-historical.md)
applies to Skill commit `42112469baacbb0765a3967197cff293e761f6aa` and remains
available with its original evidence. It also failed the negative-activation
gate, with one Jetson false activation. The case-specific outcomes and review
interpretations differ, so do not attribute the difference between runs solely
to the Skill revision or claim a stable trend from two single-pass measurements.

The evaluator uses the same model family, and the fixture is not a real engine.
These are project-owned Codex harness results, not NVIDIA SkillEvaluator
certification. They cannot replace real hardware tests, production quality
evaluation, or repeated behavioral trials. Skill files were not tuned or
rewritten after observing this run's failures.
