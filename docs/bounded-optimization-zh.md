# 有边界的配置选择

LocalPilot 的定位仍是任务驱动的推理验收与配置交付。本次只补齐已有候选的
业务门槛和选择规则，不增加自动下载模型、自研训练、无限参数搜索或后台改配置。
Skill 负责理解目标和解释结果；CLI 负责测量、判定和保存；推理引擎执行配置。

## 保持质量，选择完整响应最快的配置

在实际使用的基准配置中加入：

```json
"acceptance": {
  "objective": "fastest_complete",
  "min_quality": 1.0
}
```

仅对当前确定性字段数据集，`min_quality: 1.0` 表示整张文档通过率必须为 100%。
其他任务的质量指标仍取决于它的评分器，关键词分数不能等同于业务准确率。
需要“质量不下降”时，应使用同一验收集和评分器，把已确认的基线质量设为门槛。
这不是自动推断基线或保证未见样本质量不下降。

通过质量和稳定性门槛后，按照完整响应平均耗时选择，不用首字时间代替完成时间。

## 限定等待时间，选择质量最高的配置

```json
"acceptance": {
  "objective": "highest_quality",
  "min_quality": 0.95,
  "max_total_latency_ms": 10000
}
```

先淘汰质量低于门槛、稳定性不达标或完整响应平均耗时超过 10 秒的候选，再选择
质量最高者；质量相同则选完整响应更快者。10 秒是配置示例，不是已验证承诺。
门槛使用基准的样本平均值，不保证每一次请求或 P95 都满足。

## 使用方式

复制已有基准配置，添加 `acceptance`，并通过环境变量指定它：

```bash
LOCALPILOT_BENCHMARK_CONFIG=/path/to/benchmark-with-acceptance.json \
LOCALPILOT_VLLM_BASE_URL=http://127.0.0.1:8000 \
python3 -m localpilot.cli autopilot '本地图片字段提取，质量优先' \
  --mode vllm --no-reuse --json
```

远程执行时，配置文件和环境变量必须位于执行节点。文件内容中的 `acceptance`
参与配置哈希，策略变更会使旧验收 Profile 不能直接复用。不要修改已归档实测
对应的数据集来冒充旧实验使用了新策略。

报告记录验收策略、完整响应时间和淘汰原因。所有候选不达标时，返回门槛错误，
不会因为没有可用候选就降低门槛。候选再次评分时会清空旧分数，避免沿用旧结论。

## 当前交付边界

- 未指定策略时，沿用现有 priority 加权排序；可用 `weighted` 在原排序上增加门槛。
- 仍受现有候选数量与设备能力约束；接入一个已有服务不会自动变成多个真实配置。
- 单候选通过仅表示该配置达到本轮门槛，不能声称调优收益。
- 本次验证的是决策逻辑与模拟集成，没有新增实机加速结论。
- 应用配置继续使用现有 stage / drain / activate / resume 流程；此策略不会自行切换在线服务。
