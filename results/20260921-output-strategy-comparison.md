# DGX Spark 输出策略加速对照

2026-09-21，使用代码提交 `d21d3fd`，在同一台授权 DGX Spark GB10 上，
对现有 Step3-VL-10B-FP8 / vLLM 0.15.1+befbc472 服务执行单因素对照。

## 对照结果

| 指标 | 默认文本输出 | JSON Schema 输出 |
|---|---:|---:|
| 平均完整响应 | 9.764 秒 | 3.138 秒 |
| 平均首字时间 | 97.23 ms | 96.84 ms |
| 平均输出 token | 194.33 | 61.83 |
| 字段精确匹配 | 60/60 | 60/60 |
| 完整文档通过 | 12/12 | 12/12 |
| 失败或截断 | 0 | 0 |

相对于本轮默认文本基线，平均完整响应时间减少 **67.86%**，
基线耗时约为约束输出的 **3.11 倍**。
两轮分别约 3.11 倍；12 组配对的新策略均更快。

这里是 **6 张独立合成图片、每张每个策略重复两次**，不是 12 张独立样本。
质量来自同一次被计时的响应，按 JSON 字段、值和类型核对；标准答案没有发送给模型。
Schema 只限制字段结构和类型，不含发票编号、金额等答案。

## 固定条件与选择规则

- 只改变请求中的 `response_format`，其余线上的请求字段做了相等性检查。
- 同一模型、FP8、vLLM、GPU、上下文配置、图片和提取指令。
- 单并发，temperature 为 0，最大输出预算均为 768 token。
- 每个策略先预热一次，计分请求按图片与轮次交替 AB/BA 顺序，总计 24 次。
- 前后可观察的服务配置一致；未启动、停止或重启模型服务。
- 预先规定：字段全部正确、完整结束，且平均完整响应至少减少 10%，才推荐新策略。

JSON Schema 策略通过了上述门槛。首字时间基本相同，而输出 token 显著减少，
因此证据支持“减少生成内容降低等待时间”，不支持“GPU 每 token 推理提高 3 倍”。

## 证据边界

- 本次是暖服务上的小样本对照，保留已有缓存；不代表冷启动性能。
- 使用的是 6 张干净英文合成票据，不能据此声称生产 OCR 准确率为 100%。
- 历史普通票据验收的 12.35 秒没有作为本轮加速比例分母；本轮基线是重新测得的 9.76 秒。
- 这是请求策略选择，不是模型权重、引擎内核或显存参数优化。
- 通用 API 的默认输出方式未改变；使用这项优化需要发送对应 response_format。

配对选择后，标准 `autopilot` 流程再次验收：6 张图、30/30 个字段正确，
3 次独立性能请求平均完整响应 3.069 秒。保存的 Profile 为
`52b256d0a4915bbff292`，运行 ID 为 `d4e95a9e-20cc-4d6f-8ee7-9ce61b7f2e3a`。
这是独立复验，不与两轮配对数据混算。

使用已交付的验收配置复现：

```bash
LOCALPILOT_BENCHMARK_CONFIG=results/20260921-json-schema-benchmark.json \
LOCALPILOT_VLLM_BASE_URL=http://127.0.0.1:8000 \
python3 -m localpilot.cli autopilot '本地发票图片字段提取，单用户质量优先' \
  --mode vllm --no-reuse --json
```

该命令在推理节点运行，并要求已有支持该模型与输出约束的 vLLM 服务。
应用自己的图片时，沿用字段类型 Schema，将图片和提取要求传入请求；
新增 `response_format` 已接入 LocalPilot 的流式与非流式请求构造。
已保存 Profile 只证明验收和记忆，不意味着通用 API 已自动采用此格式。
